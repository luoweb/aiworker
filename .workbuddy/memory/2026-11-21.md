## 修复 VS Code 插件模型选择的软件渲染黑块

- 用户报 VS Code 插件模型选择同样出现黑色遮罩，参考 `3a9197bb`（移除模型选择器基于 `mask-image` 的滚动渐隐）。
- 排查结论：当前 HEAD 的 `ModelPickerList` 已经同时传 `hideTopScrollShadow`/`hideBottomScrollShadow`，列表本身的 mask 已被抑制；但残留了只服务旧 sticky fade 的死代码和 CSS，且 `CustomProviderModelDiscovery` 的模型列表仍开着 `useScrollShadow`（真实 mask 风险）。
- 改动：
  - `ModelPickerList.tsx`：彻底不挂 `ScrollShadow`，删掉 `stuckSectionHeaders`、`sectionHeaderSentinelRefs`、`visibleSectionKeys`、IntersectionObserver effect、`stuckSectionKey`、隐藏的 sticky fade 按钮；保留 `stickyHeaders` 给 `scrollPaddingStart`。
  - `index.css`：删除已无人使用的 `.oc-sticky-fade-overlay` / `.oc-sticky-fade-root` 规则。
  - `CustomProviderModelDiscovery.tsx`：模型发现列表去掉 `useScrollShadow`。
  - `model-picker/DOCUMENTATION.md`：补上「Why there are no scroll fades」，并纠正此前声称存在 sticky caption 的错误描述。
  - `ModelPickerList.screenReader.test.tsx`：加不变量测试，断言不挂载 `[data-scroll-shadow]` 与 `.oc-sticky-fade-overlay`。
- 验证：`bunx tsc --noEmit -p packages/ui/tsconfig.json` 零诊断；`bun test packages/ui/src/components/model-picker/` 11/11 通过；复核代理未发现真实回归。
- 未覆盖：`vscode:dev` 的 Vite dev server 被沙箱的批量删除保护挡住（`node_modules/.vite/deps` 1150 项），没能在 VS Code webview 里目视确认；若黑块来自下拉弹层的 `oc-glass-popover` 半透明底色而非滚动 mask，本次改动不会消除它。
