## 修复 web scheduler 与模型选择框底部滚动遮罩变黑

- 根因：`packages/ui/src/index.css` 中 `[data-bottom-scroll="true"]` 的滚动阴影用了 `mask-image: linear-gradient(... #000 ...)`，软件渲染环境（远程桌面、旧 GPU）会栅格化为实心黑块。
- 修复方式：复用 `ScrollableOverlay` 已有的 `hideBottomScrollShadow` prop（透传到 `ScrollShadow` → `useScrollShadow`，使 `hasAfter=false`，不再设置 `data-bottom-scroll`，从而不匹配那条 mask 规则）。
  - `packages/ui/src/components/session/ScheduledTaskEditorDialog.tsx`：桌面 dialog 的 `ScrollableOverlay` 已有 `hideTopScrollShadow`，补上 `hideBottomScrollShadow`；原本注释 "No scroll fades here" 与实际一致了。
  - `packages/ui/src/components/model-picker/ModelPickerList.tsx`：给列表滚动容器加 `hideBottomScrollShadow`，保留顶部 fade（sticky 分组标题依赖 top-scroll 状态）；更新注释与 `model-picker/DOCUMENTATION.md` 决策条目。
- 验证受限：仓库依赖未安装（`bun install` 未跑），`bun run type-check:ui` 报缺 `@types/node`/`@types/dom-speech-recognition`，聚焦测试缺 `react/jsx-dev-runtime`。改动为已有合法 prop 的透传，未新增逻辑。bun 在 `/config/.bun/bin/bun`，不在默认 PATH。

## 修复设置外观页主题列表遮罩变黑

- `ThemeAppearancePicker.tsx` 的 `ThemeList` 没走 `ScrollableOverlay`，而是手写三条 inline `[mask-image:linear-gradient(...#000...)]`（上下/仅上/仅下），同样在软件渲染下变黑，`hideBottomScrollShadow` 对它无效。
- 修复：移除三条 mask，删掉只服务于它们的 `fade` state / `updateFade` / `onScroll` / effect 调用，把 `LIST_FADE_PX` 改名 `LIST_PAD_PX`（对应列表 `py-3` 内边距，用于 revealSelected 定位），更新注释。`sections/DOCUMENTATION.md` 加决策条目。
- 教训：这类变黑有两个入口 —— 走 `ScrollShadow` 的用 `hideBottomScrollShadow`/`scrollShadowSurface`；手写 inline `mask-image` 的只能直接删 mask。排查时两者都要看。
