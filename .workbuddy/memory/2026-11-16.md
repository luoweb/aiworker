## 修复 web scheduler 与模型选择框底部滚动遮罩变黑

- 根因：`packages/ui/src/index.css` 中 `[data-bottom-scroll="true"]` 的滚动阴影用了 `mask-image: linear-gradient(... #000 ...)`，软件渲染环境（远程桌面、旧 GPU）会栅格化为实心黑块。
- 修复方式：复用 `ScrollableOverlay` 已有的 `hideBottomScrollShadow` prop（透传到 `ScrollShadow` → `useScrollShadow`，使 `hasAfter=false`，不再设置 `data-bottom-scroll`，从而不匹配那条 mask 规则）。
  - `packages/ui/src/components/session/ScheduledTaskEditorDialog.tsx`：桌面 dialog 的 `ScrollableOverlay` 已有 `hideTopScrollShadow`，补上 `hideBottomScrollShadow`；原本注释 "No scroll fades here" 与实际一致了。
  - `packages/ui/src/components/model-picker/ModelPickerList.tsx`：给列表滚动容器加 `hideBottomScrollShadow`，保留顶部 fade（sticky 分组标题依赖 top-scroll 状态）；更新注释与 `model-picker/DOCUMENTATION.md` 决策条目。
- 验证受限：仓库依赖未安装（`bun install` 未跑），`bun run type-check:ui` 报缺 `@types/node`/`@types/dom-speech-recognition`，聚焦测试缺 `react/jsx-dev-runtime`。改动为已有合法 prop 的透传，未新增逻辑。bun 在 `/config/.bun/bin/bun`，不在默认 PATH。

## 修复集成页分类 chip / 统计页时间栏未选中态变黑

- 定位过程走了弯路：两个探索 agent 都说目标组件没有 mask，因为这次根因不是 `mask-image`，而是 `bg-[color-mix(in_srgb,var(--foreground)_N%,transparent)]` 半透明背景。用户描述"未选中黑、选中正常"是决定性线索：未选中态用半透明 color-mix，选中态用不透明的 `aria-pressed:bg-interactive-selection`。
- 软件渲染下半透明 color-mix 也栅格化为实心黑块（与 mask-image 同一类 GPU bug）。
- 修复：在两处调用点用 `cn` 覆盖，把 transparent 换成 `var(--background)` 得到视觉等价的不透明色，不动共享组件。
  - `IntegrationsCatalogView.tsx`：加 `CATEGORY_CHIP_TINT` 常量，用在 All 与分类 chip 的 className。
  - `usage/UsageStatsView.tsx`：给 `SettingsChipGroup` 传 className 覆盖轨道背景。
- 关键验证：用 openchamber 副本的 node_modules（主工作区无 node_modules）跑 tailwind-merge，确认后传入的 `bg-[color-mix(...,var(--background))]` 能覆盖前置的 transparent 版本，其他类保留。验证命令：`NODE_PATH=/code/aiworker/openchamber/node_modules node -e "..."`。
- 经验：排查这类"变黑"要有第三个入口 —— 半透明 `color-mix(...,transparent)` 填充，不止 mask-image 和 scroll shadow。用户在软件渲染环境（远程桌面/旧 GPU）。`sections/DOCUMENTATION.md` 已补充通用规则。

## 修正统计页时间栏凹槽黑底

- 上一轮把统计页轨道的 `color-mix(...transparent)` 换成 `var(--background)` 后用户仍报"今天/7天/90天不选中就是黑色背景"。真正原因不是 tint，而是 `SettingsChipGroup` 外层的 `oc-recessed` 凹槽：`box-shadow: inset 0 1px 2px rgb(0 0 0/0.05)`（深色 0.4）+ 淡 tint 在未选中按钮背后读成黑块，选中态的不透明 pill 盖住了它，所以只有未选中显黑。
- 修复：`UsageStatsView.tsx` 给该处 `SettingsChipGroup` 传 `className="bg-transparent !shadow-none"`（注意 bg 用普通值以便 tailwind-merge 移除旧 tint，阴影必须 `!` important 才能压过 `.oc-recessed` 的普通 class 规则），让 chips 直接落在页面背景上。
- tailwind-merge 验证：`twMerge(base, 'bg-transparent !shadow-none')` → 旧 `color-mix` tint 被移除，两条覆盖类保留。`!bg-transparent` 反而会保留旧 tint，故 bg 不加 `!`。
- 注意：用户运行的是主工作区副本，`openchamber/` 是独立 git 仓库的另一套实现，其 `variant="chip"` 用 `bg-transparent`，时间栏用 chip 而非 SettingsChipGroup，不受此问题影响。改代码认准 `/code/aiworker/packages/ui`。
